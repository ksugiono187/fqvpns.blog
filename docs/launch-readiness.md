## 正式上线仍需账户侧完成

1. 在Cloudflare Pages连接仓库 main，构建命令 `npm run build`，输出 `dist`，使用Node24。核对锁文件安装和构建日志。
2. 绑定fqvpns.blog并核对DNS、HTTPS、主域跳转和404响应。预览域名的访问与索引限制在托管配置中处理。
3. 登录Bing Webmaster Tools验证站点，提交Sitemap，核对实际抓取。IndexNow Key必须先在正式域名可访问，再提交已上线的新增/修改地址。
4. 补充维护者实际运营联系渠道；当前使用GitHub Issues纠错入口，不虚构邮箱。

本轮无法通过公开网页工具访问正式域名，因此没有标记正式上线成功。已有GitHub推送也不能证明Cloudflare已部署。

Cloudflare部署配置按[官方Astro部署说明](https://developers.cloudflare.com/pages/framework-guides/deploy-an-astro-site/)复核；账户侧详细步骤见deployment.md与bing-webmaster.md。

## 资料更新规则

- 每次核对原始来源后修改数据，保留来源地址、读取日期和争议说明；不能把构建日期写成新的官方核验日期。
- 大佬云缺少指定来源；Firefly、极连云存在套餐归属疑点，取得明确对应资料前不进入金额排行。
- 唯兔云至尊档容量冲突、浪网入门档容量不明，不能补猜测值。
- 流量倍率、线路地区、设备限制、退款与平台支持，当前没有完整证据；取得资料后区分服务方声明和本站实测。
- 实测发布需记录时区、设备、运营商、客户端、节点、目标与重复尝试，保存失败记录；未测试不得创建速度或稳定性名次。
- 优惠码需记录验证日期、适用套餐、优惠幅度、期限与续费规则；没有实际核销证据时不自动计算折扣。
- 更新数据后依次运行检查、测试、构建和审计，并在手机查看筛选、比较和表格。
